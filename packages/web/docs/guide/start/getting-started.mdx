# Build your first service

Start with one useful operation. A Nile **service** groups a domain's work, and an **action** exposes one operation with its input checks and handler. The same pattern gives the next teammate somewhere familiar to start.

## Start from the template

```bash
bunx @nilejs/cli new my-app
cd my-app
bun install
bun run dev
```

The current template selects Bun native, registers a tasks service, and includes PGLite with Drizzle. Its startup hook creates the example tasks table. It explicitly enables discovery for development; discovery is otherwise off by default.

Generate the next service or action from the project directory:

```bash
bunx @nilejs/cli generate service projects
bunx @nilejs/cli generate action projects archive
```

Prefer your own data layer? The manual example below has no database dependency.

## A complete first operation

Install the core package and the two libraries used in this example:

```bash
bun add @nilejs/nile zod slang-ts
```

Create `server.ts`:

```typescript
import { createAction, createNileServer, createServices } from "@nilejs/nile";
import { Ok } from "slang-ts";
import { z } from "zod";

const createProjectSchema = z.object({
  name: z.string().trim().min(1),
});

type CreateProjectInput = z.infer<typeof createProjectSchema>;

const createProject = createAction<CreateProjectInput>({
  name: "create",
  description: "Create a project",
  validation: createProjectSchema,
  handler: (input) => Ok({
    project: { id: crypto.randomUUID(), name: input.name },
  }),
});

const services = createServices([
  {
    name: "projects",
    description: "Organize the team's projects",
    actions: [createProject],
  },
]);

const server = await createNileServer({
  serverName: "Team workspace",
  runtime: "bun",
  native: true,
  services,
  rest: {
    baseUrl: "/api",
    allowedOrigins: ["http://localhost:3000"],
    enableStatus: true,
  },
});

const native = server.nativeRest;
if (!native) throw new Error("Bun native transport was not initialized");

Bun.serve({ port: 8000, fetch: native.fetch });
```

This example returns a new project without persisting it. Add storage through your application's model or repository when you need it.

`createNileServer` builds the engine and transport; it does **not** start a listener. `Bun.serve` starts this application's listener. Existing Hono applications remain supported; see [runtime adapters](/guide/start/runtime-adapters).

```bash
bun run server.ts
```

## Call the operation

```bash
curl http://localhost:8000/api/services \
  -H 'Content-Type: application/json' \
  -d '{"intent":"execute","service":"projects","action":"create","payload":{"name":"Customer portal"}}'
```

The response contains the project in a consistent envelope:

```json
{
  "status": true,
  "message": "Action 'projects.create' executed",
  "data": {
    "project": { "id": "generated-id", "name": "Customer portal" }
  }
}
```

Send an empty name and validation stops the handler with a failure response. You can call the same action from the [frontend client](/guide/basics/client).

## Keep the next change easy to find

Move this operation into a `projects` domain as the application grows. Read [application structure](/guide/start/application-structure), then [errors and Results](/guide/basics/errors-and-results) to give new operations the same recognizable shape.
