# Native NestJS and AdonisJS fixtures

These benchmark-only adapters use the class/decorator patterns approved by the owner. Nile implementation remains functional. The owner starts listening servers; fixture factories never call `listen`.

`createNest({ host: 'express' | 'fastify', mode: 'plain' | 'validated' })` initializes a Nest application with 300 decorated controllers and returns the initialized application. Each operation has a distinct native POST route. It uses the specified Nest platform adapter, body parsing, controller invocation and response serialization. Compile with legacy decorators enabled (`experimentalDecorators` and `emitDecoratorMetadata`) before running the emitted JavaScript on Node. Do not benchmark a development TypeScript loader.

`createAdonis({ mode: 'plain' | 'validated' })` creates an Adonis web application, initializes configuration, boots the core app provider, starts its lifecycle, registers 300 native router entries and boots the core server pipeline with official body-parser middleware. It returns `{ app, server, nodeServer, close }`. The Node server is created but never listens. Copy the fixture's `package.json` beside the compiled Adonis configuration so its application root remains a standard module package. Configuration contains no environment loader or environment-file access. The public fixture encryption key protects no secrets; encryption is not exercised by these workloads.

Both modes parse JSON. The validated mode uses Zod 4.6.7, accepts a nonnegative safe-integer `id` and an integer `value` from 0 through 999, and responds with `{ id, value: value + 1, action }`. Validation failures return status 400 with native framework error formatting. The plain mode performs the same transformation without validation. Application logging is disabled; Adonis request identifiers retain the standard framework behavior.

Installed versions: NestJS 12.1.3 and AdonisJS 7.6.0, checked on Node 24.16.0. Strict native compilation passes. The six non-listening cases in `tests/native-fixtures.test.mjs` pass: all 300 Nest Fastify routes in both modes return the expected transformation; five invalid inputs return status 400; both Nest Express applications register all 300 POST routes; both Adonis applications reach ready state with their core server booted and 300 routes. Every application remains non-listening. Express and Adonis checks verify registration and lifecycle, not end-to-end HTTP response behavior; the owner-started external correctness pass must cover those responses before ranking.

Adonis uses a separate `config/encryption.ts` with its normal version 7 driver configuration. The shared workload rules are reproduced exactly in the native TypeScript files; no validation or routing is bypassed in benchmark execution. New source files had no pre-change originals.
